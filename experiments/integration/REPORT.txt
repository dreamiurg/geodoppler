WHAT I KEPT / DROPPED AND WHY
(a) Rotorcraft exclusion (adsb.is_rotorcraft, filtered in cli.locate after load): kept. It removes one
    wrong-high and breaks no correct case. It drops rotorcraft from silence breaking and verify_extra too.
    The "candheli" alternative was never run. Margin costs with no bucket change: u8q 0.498 -> 0.399 (once
    helicopters stop breaking silence, more hits survive and the runner-up rises); TX52 and ZJ7e wrong margins
    rose slightly (0.011 -> 0.018, 0.014 -> 0.043).
(b) Guard 60 s + stage 2 for every combination: kept. y-xp wrong -> correct, nothing else changed bucket.
    Merged by hand onto the perf code (refine= removed from the signature and the recursive call).
(c) k flag (search.doppler_scale, Tolerances.scale_ok = 0.08, result.json "doppler_scale", map info line):
    kept, with a cost. It catches 0a7b (the last wrong-high) and flags 13 of 15 wrong answers (misses ZQBM and
    ru5b, as the wind report found). It also demotes two right answers whose spot is 0.9 km off (y-xp and
    akron, k 1.16-1.22). Correct-high falls 6 -> 5, but no correct answer becomes wrong, which the keep rule
    allows. Headroom is thin both ways: 0a7b is caught at k 1.16, and akron is falsely demoted at k 1.16.
    The threshold sits between "right answer 0.9 km off" and "wrong answer". That is the open calibration
    question.
(d) fb type filter (proptone.py with the class rule: unmapped piston => fb <= 150 Hz, unknown types pass):
    measured, then REVERTED. The port matched fbase_events.csv exactly and passed 20/20 correct matches in
    matches.csv. With the k flag in place it changes no bucket except 1Rh6_nky (wrong-low -> no match). It
    builds a new wrong 0a7b answer from blank-type aircraft at a 53 % margin, held low only by k = 0.88. It also
    raises other wrong margins (1Rh6 0.008 -> 0.103, BKW 0.061 -> 0.094). Upside, and the reason to revisit:
    J8yv 0.233 -> 0.262, and y-xp 0.086 -> 0.216 (it would be correct-high without the k flag). Fix path:
    resolve blank ICAO types (32 % of aircraft) first, so the class rule has something to act on. The code is
    in branch history (a1ec581) and the snapshot exp/integration/fbtype/src.
(e) Narrow sweep: dropped. It breaks y-xp (83 km) and y-xp_akron (7 km); their true pairs need k up to 1.2.
    The margin gains on the other correct cases were real (U1b 0.63 -> 0.79, J8yv 0.26 -> 0.76, Usy 0.11 ->
    0.23 high, 4Cx 0.19 -> 0.34; u8q fell 0.40 -> 0.27). Snapshot only, not on the branch.
